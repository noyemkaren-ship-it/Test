# Воспроизводимая проверка Graph Platform

Этот файл описывает не оценку автора, а процедуру, которую заказчик или другой разработчик может повторить на чистой копии репозитория.

## Полная проверка одной командой

Требования: Node.js 20+, npm, Python 3.10+ и `curl`.

```bash
./scripts/audit.sh
```

Сценарий выполняет `npm ci` по lock-файлам, `npm audit` для frontend/backend, TypeScript-проверку, production build, синтаксическую проверку каждого backend-файла и Python-модулей. Затем он создаёт временную SQLite-базу, запускает изолированный backend и выполняет интеграционный smoke-тест. Временная база и процесс удаляются автоматически.

Если зависимости уже установлены строго по lock-файлам:

```bash
GP_AUDIT_SKIP_INSTALL=1 ./scripts/audit.sh
```

Успех подтверждается последней строкой:

```text
AUDIT RESULT: PASS
```

## Что доказывает интеграционный smoke

- public read и запрет guest-записи;
- регистрация, `auth/me` и личный workspace;
- приватный граф и cross-workspace isolation;
- создание, чтение, изменение и удаление узлов;
- создание, чтение, изменение и удаление связей;
- запрет cross-graph relation;
- сохранение координат drag & drop в SQLite;
- FSM и переход состояния;
- Default First ontology и graph-scoped extension;
- RAG ingest и поиск с привязкой к узлам;
- Review create/read;
- template snapshot с сохранением layout;
- Graph Copilot с выбранным узлом и RAG-контекстом;
- очистку тестовых сущностей.

## Почему проверка независимая

Сценарий не использует рабочую БД и не доверяет заранее подготовленным данным. Для каждого запуска создаются новый пользователь, новый workspace, новый private graph, новые узлы, связь, документ, review и template. Проверка завершается ошибкой при первом несовпадении факта с ожидаемым результатом.
