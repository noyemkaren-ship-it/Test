Было:

- обзор открывается отдельной кнопкой «О платформе»;
- режим «Презентация» сохранён как дополнительный, а не основной сценарий.

1.6. Сохранение layout

Было:
- позиции определялись frontend-константами;
- перетаскивание не доказывало долговременное сохранение.

Стало:
- React Flow использует сохранённую позицию node.data.position;
- после drag stop координаты отправляются на backend;
- backend валидирует конечные числовые x/y;
- координаты записываются в nodes.data_json;
- GET /api/graph/nodes возвращает их после нового запроса;
- template snapshot также сохраняет layout.

Статус: ИСПРАВЛЕНО И ПОКРЫТО ИНТЕГРАЦИОННЫМ ТЕСТОМ.

1.7. Защита операций редактора

Добавлено и подтверждено:
- guest может читать public graph, но не может изменять данные;
- запись требует JWT или разрешённый service access;
- пользователь может изменять только граф workspace, участником которого он является;
- private graph другого workspace не читается и не изменяется;
- узлы из разных графов нельзя соединить одной связью;
- без выбранного graph редактирование не выполняется.

Статус: ИСПРАВЛЕНО И ПРОВЕРЕНО.

1.8. Расширение онтологии без отложенного применения

Во время нового аудита обнаружено:

Исправление:

- новый тип доступен уже в ответе POST /api/ontology/extend;

======================================================================

Первоначальный этап требовал перенос HTML-прототипа и сохранение функций графового редактора. Текущий проект вышел далеко за пределы этого объёма. В репозитории фактически присутствуют:

- 20 таблиц SQLite с WAL и foreign keys;
- 61 зарегистрированный HTTP route handler;
- 24 backend JavaScript-модуля;
- 21 frontend TypeScript/TSX-модуль;
- public read / protected write модель;
- отдельные private workspace и membership-проверки;
- независимые доменные графы;
- Graph Copilot с контекстом выбранных узлов, связей, Work Items и RAG;
- offline-first fallback для AI;
- RAG ingest, chunking, токенизация и graph-scoped retrieval;
- FSM для Task, Defect, ReviewComment, ChangeRequest, KnowledgeDefect, Risk, TechnicalDebt и Improvement;
- расширяемая Default First ontology;
- Reviews как отдельные данные графа;
- templates/snapshots и клонирование структуры;
- Actor, role bindings и Interest Scope;
- четыре слоя: Knowledge, Implementation, Project, Resource;
- ролевые проекции «Руководитель», «Аналитик», «Разработчик», «Инженер ИИ»;
- автоматическая подсветка связанных узлов и приглушение нерелевантного контекста;
- отдельная вкладка настроек;
- русский и английский языки;
- тёмная, светлая и системная темы;
- изображения в обзорном разделе;
- responsive interface и presentation mode;
- административная консоль;
- воспроизводимый security/build/integration audit.

Поэтому корректная итоговая формулировка следующая:

ПЕРВЫЙ ЭТАП ВЫПОЛНЕН НА 100%, А ОБЪЁМ ТЕКУЩЕЙ ПЛАТФОРМЫ СУЩЕСТВЕННО ПРЕВЫШАЕТ ПЕРВОНАЧАЛЬНОЕ ТЗ ПЕРВОГО ЭТАПА.

При этом данный отчёт не подменяет отдельный production roadmap: переход к распределённой БД, внешнему rate limiter, полноценной телеметрии и кластерному deploy является самостоятельным следующим этапом, а не незакрытым CRUD-дефектом React Flow.

510af02 New commit

Проверяемые факты:

- уже первый доступный commit содержит v3-архитектуру;
- runtime использует better-sqlite3;
- backend/src/HoneyOrm.js прямо помечен как ARCHIVED PROTOTYPE и не используется runtime v3;

Принятое технически честное решение:

- текущий репозиторий проверяется и сдаётся как самостоятельная версия v3;
- неподтверждённая связь со старым внешним репозиторием больше не заявляется;
- для восстановления внешней истории нужен первичный артефакт: архив с .git, commit hash, URL/remote или подписанный export;
- отсутствие внешнего архива не смешивается с функциональной готовностью текущего кода.

Таким образом, противоречие в отчётности закрыто: вместо трёх несовместимых историй теперь существует одна проверяемая позиция с явно проведённой границей доказательств.
